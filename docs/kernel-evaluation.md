# 内核评估报告（P0 · Linux 部分）

> 2026-10-21。Windows 和 macOS 部分待你在自己的电脑上运行测试脚本后补充。
> 评估工具和原始结果在 `folio/p0-kernel-eval/`（`eval/` 是脚本，`results/` 是每个用例的 JSON 和截图）。

## 1. 结论

两个内核都能用，但各有几项**必须由启动适配器显式处理**，不能交给内核的默认值：

| | Chromium（fingerprint-chromium） | Firefox（Camoufox） |
|---|---|---|
| 身份能否稳定复现 | 能。同一个种子两次启动，Canvas、音频、WebGL 完全一致 | 部分能。启动库每次都会重新生成身份，所以必须由我们保存完整配置；保存后音频、屏幕、GPU 都能稳定复现，但 **Canvas 做不到「每个环境稳定且互不相同」**（见下文） |
| 必须显式设置的项 | 时区、语言、地理位置（含精度）、WebRTC 策略 | 时区、语言、地理位置、CPU 核数、WebRTC IP、音频种子 |
| 不处理会怎样 | 地理位置默认拿不到；手动设置时精度为 0，很可疑 | 时区暴露本机时区，CPU 核数暴露本机真实核数，WebRTC 暴露真实公网 IP |
| 控制粒度 | 粗：大部分由一个种子决定，GPU 型号不能单独指定 | 细：133 个可配置属性 |
| 启动耗时 | 0.4–0.8 秒 | 2.4–3.3 秒；某个系统的字体第一次被使用时要建索引，那次启动约 165 秒 |
| 安装包 | 约 150–190 MB | 每个平台约 1.3 GB，解压后 2.4 GB（其中约 2 GB 是字体） |

**Firefox 内核的 Canvas 两难**：从 156.0.1-beta.32 起，Camoufox 删除了 Canvas 种子和字体间距种子（PR #779：为了和原版 Firefox 的文字测量结果完全一致，关掉了按每次启动扰动字形）。剩下的规则是：伪装的系统或 GPU 和本机不一致时，Canvas 自动加随机噪声，每次启动都不同；一致时不加噪声，Canvas 就是这台电脑的真实值。所以：
- 和本机一致的 Firefox 环境，同一台电脑上所有环境的 Canvas 都相同，可以被关联起来；
- 和本机不一致的 Firefox 环境，同一个账号每次登录的 Canvas 都不同，而且随机读回本身就是隐私加固版 Firefox 的特征。

两种情况都不适合「一台电脑开很多个账号」。Chromium 内核没有这个问题（同一个种子稳定，不同种子不同）。**建议：新建环境默认用 Chromium 内核，Firefox 作为可选项，并在界面上说明这个限制。** 真实显卡下的表现由电脑版测试脚本验证（它在同一台电脑上开两个不同的 Firefox 身份做对比）。

**对产品的影响**（P2 实现时照此修改设计稿和官网文案）：
1. 一致性检查里的「WebRTC 只显示代理 IP」要按内核区分：Chromium 内核是「WebRTC 已阻断，不泄露真实 IP」，Firefox 内核才是「替换为代理出口 IP」。
2. Chromium 环境不能指定 GPU 型号。界面只读显示由种子生成的 GPU，提供「换一个」来更换种子。Firefox 环境可以从该系统下真实记录过的 GPU 列表里选。
3. Chromium 环境的屏幕分辨率跟随本机，不能伪装，界面显示为「跟随本机」。
4. 官网和设计稿里的「25 项参数」要改成两个内核实际能控制的项目（见第 3 节）。
5. Firefox 环境伪装成和本机不同的系统时，Canvas 会被加噪声，这本身就是一个可被识别的特征。界面要提示建议让 Firefox 环境的系统和本机保持一致。
6. Camoufox 的字体包含苹果和微软的商业字体（例如冬青黑体），产品要再分发这个包，需要先做法律确认（见第 6 节）。

## 2. 测试条件和局限

- 内核全部在 Docker 容器里运行（Xvfb 虚拟显示，没有显卡），没有在宿主机上直接执行。容器限制为 6 GB 内存、4 核 CPU。
- 公司出口代理会对外部网站做 TLS 解密转发。所以外部检测网站看到的是代理的 TLS 指纹，不是浏览器的；出口 IP 也是公司在吉隆坡的出口。**外部检测结果只能作参考**，TLS 指纹类检测必须在正常网络下重做。
- 容器里没有显卡、语音引擎和媒体设备，所以这几项只能说明「内核是否伪装」，不能说明真实电脑上的效果。

| 组件 | 版本 | 许可证 |
|---|---|---|
| fingerprint-chromium | 150.0.7871.186（Linux） | BSD-3-Clause |
| Camoufox 浏览器 | 156.0.1-beta.36 | MPL-2.0 |
| camoufox（npm 启动库） | 0.5.8，带发布来源证明，仓库为 daijro/camoufox | MIT（依赖 fpgen-js，Apache-2.0） |
| playwright-core | 1.62.0 | Apache-2.0 |

**Playwright 版本被锁定**：Camoufox 要求 playwright-core 低于 1.63，因为每个小版本都可能改动 Firefox 的控制协议。两个内核共用同一个 Playwright，所以工作台锁定 1.62.x，升级要等 Camoufox 放开版本上限。

## 3. 指纹覆盖情况

「观察结果」一栏是容器里实测到的值。

| 指纹项 | Chromium（fingerprint-chromium） | Firefox（Camoufox） |
|---|---|---|
| 操作系统 / UA | 平台开关设为 windows、macos 或 linux。UA 和客户端提示（UA-CH）一致，系统版本也是合理值（Windows 19.0.0、macOS 15.1.0） | 用 `os` 选项设置；UA 为 Firefox 156 |
| CPU 核数 | 开关设置，生效 | **默认不伪装**：所有用例都是 20，就是宿主机的真实核数。必须在配置里设 `navigator.hardwareConcurrency` |
| GPU（WebGL 厂商和型号） | 由种子决定，且和平台匹配（Windows 是 Intel Iris Xe + D3D11，macOS 是 Apple M2 + Metal）；不能指定具体型号 | 从该系统的真实记录里抽取，也可以从记录列表里指定；型号后缀带「, or similar」，和真实 Firefox 一致 |
| 设备内存 | 由种子决定（32 / 16） | Firefox 本来就没有这个接口，属于正常现象 |
| 屏幕分辨率 | **不伪装**，跟随本机 | 伪装（配置里的 `screen.*`） |
| 窗口大小 | 跟随本机 | 伪装 |
| 字体 | 按平台伪造字体列表：没装 Windows 字体，也能测到 Cambria、微软雅黑、宋体 | 随包附带各系统的字体文件，约 2 GB |
| 语言 | 开关设置，生效 | 生效 |
| Navigator（webdriver 等） | webdriver 为 false；5 个 PDF 插件（现代浏览器的标准值） | 同左 |
| 时区 | 开关设置，生效 | 配置设置，生效；**不设置就是本机时区** |
| 地理位置 | 没有开关；通过 Playwright 授权并设置坐标可以生效，但精度默认为 0，必须同时设一个真实范围的精度 | 配置设置，生效（精度约 750 米）；不设置时网页会卡在权限请求上 |
| WebRTC | 用 `--disable-non-proxied-udp` 完全阻断，不产生任何候选地址，不泄露 | **默认泄露真实公网 IP**（STUN 不经过代理）。必须设置 `webrtc:ipv4/ipv6` 为出口 IP，或者禁用 WebRTC |
| Canvas | 同一个种子稳定，换种子就变 | 容器里每次启动都不同（伪装的 GPU 和本机不一致，噪声自动开启）。`canvas:seed` 已在 156.0.1-beta.32 删除，设了也没用。见第 1 节「Canvas 两难」 |
| WebGL 图像 | 同一个种子稳定，换种子就变 | **不同身份之间完全相同**，同一台电脑上的多个环境可能因此被关联起来，待真实显卡复核 |
| 插件 | 5 个 PDF 插件 | 同左 |
| 音频 | 由种子决定，稳定 | 每个身份不同，相同配置下稳定 |
| 电池 | 返回本机真实值（台式机通常是「充电中、100%」） | 没有这个接口，和真实 Firefox 一致 |
| ClientRects | **不同种子之间也相同**，可能被用来关联同机环境，待真实电脑复核 | 随系统和字体变化 |
| 语音列表 | 跟随本机（容器里为 0） | 伪装（Linux 身份 131 个，Windows 身份 11 个） |
| 媒体设备 | 跟随本机 | 可以配置 |

## 4. 自动化特征和外部检测（仅供参考，见第 2 节）

- **Sannysoft**：两个内核的自动化相关检测全部通过（WebDriver、Selenium、Phantom、无头 Chrome）。Firefox 的「Chrome 对象缺失」属于正常现象。
- **CreepJS**：Firefox 内核的无头特征 0%、隐身插件特征 0%、「像无头浏览器」6%。Chromium 内核在没有 WebGL 时为 0%、0%、44%，那 44% 主要来自容器里缺少显卡、语音和媒体设备；打开软件 WebGL 之后，CreepJS 页面会崩溃，待真实电脑复核。
- **两种启动方式的检测结果相同**：Chromium 由我们自己拉起进程、再通过 CDP 连接，或者由 Playwright 直接启动（去掉 `--enable-automation`），webdriver 都是 false，各项检测结果都一样。

## 5. 对启动适配器的具体要求

**Chromium**
- 推荐由 Playwright 启动，走管道（pipe）通信。自己拉起进程的方式需要在本机开一个调试端口，本机任何程序都能连上来控制浏览器。启动参数要去掉 `--enable-automation`。Playwright 默认还会加一批参数，P2 要逐个审查。
- 环境配置里保存：种子、平台、品牌、CPU 核数、语言、时区。这样每次启动生成的身份完全一致。
- 地理位置通过 Playwright 设置，必须带精度。
- WebRTC 固定使用 `--disable-non-proxied-udp`。

**Firefox**
- 通过 camoufox 启动库启动。新建环境时生成一次完整配置，存到服务端；之后每次都传入同一份配置，绝不让启动库重新生成身份。
- 配置里必须显式写入：时区、语言、地理坐标和精度、`navigator.hardwareConcurrency`、`webrtc:ipv4/ipv6`（出口 IP）、`audio:seed`。容器里已验证这几项都生效：核数变成配置值，WebRTC 的候选地址被替换成配置的 IP，音频在两次启动之间一致。不要再写 `canvas:seed` 和 `fonts:spacing_seed`，这两项已被删除。
- 关掉启动库的所有联网行为：排除默认的 uBlock Origin（`exclude_addons: ['UBO']`，否则每次启动都会去 addons.mozilla.org 下载）；不用它自带的 GeoIP，出口 IP 和地理位置由我们的服务端检测（PLAN 6.4），直接写进配置。
- Playwright 脚本默认运行在隔离环境里，读不到页面自己的 JS 变量。工作流里的「执行脚本」步骤在 Firefox 内核下要加 `mw:` 前缀，切到页面环境执行。
- 某个系统的字体第一次被使用时，启动要几分钟。安装后可以预热，或者在界面上提示「首次启动较慢」。

**两个内核共同的结论**
- Cookie 都能用 Playwright 导出，再导入一份全新的用户数据目录，登录状态保留。PLAN 6.3 的同步方案可行。
- 本地代理转发器的原型（`eval/forwarder.mjs`）在两个内核下都能正常使用：浏览器不带认证连本地端口，由转发器负责上游代理的认证。

## 6. 风险

1. **字体授权**：Camoufox 的字体包里有 macOS 和 Windows 的系统字体。再分发这些字体可能侵犯苹果和微软的权利，需要法律确认。备选方案是去掉这些字体包，只用本机字体，代价是 Firefox 环境不能再伪装成别的系统。
2. **安装包体积**：Camoufox 每个平台约 1.3 GB，不适合打进安装包。应该在用户第一次新建 Firefox 环境时，从我们自己的下载源按需下载，下载后校验哈希。
3. **同机关联**：Chromium 的 ClientRects 和 Firefox 的 WebGL 图像，在不同身份之间完全相同，可能被用来把同一台电脑上的多个环境关联起来。需要在真实电脑上复核；如果确实如此，要向用户说明这个已知限制。
4. **macOS 上的 Chromium 版本落后**：fingerprint-chromium 的 macOS 版本只到 148（其他平台是 150），而且架构未知，测试脚本会检查。

## 7. 待在 Windows 和 macOS 上复核

- 真实显卡下，每个身份的 WebGL 型号和 WebGL 图像
- ClientRects 在不同身份之间是否仍然相同
- CreepJS 的完整结果（容器里会崩溃）
- 正常网络下的 TLS 指纹（JA3/JA4），以及出口 IP 和时区是否一致
- 每个环境运行时的内存占用
- macOS 版 fingerprint-chromium 148 的架构（Intel 还是 Apple 芯片）
- 未签名的内核二进制会不会被 SmartScreen 或 Gatekeeper 拦截
